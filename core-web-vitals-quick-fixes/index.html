Core Web Vitals quick fixes

Core Web Vitals are Google’s names for whether a page feels fast and stable: how quickly the main content appears (LCP), how soon the page responds to a tap (INP), and whether the layout jumps while it loads (CLS). You do not need to memorise the acronyms. You need to fix the things that usually cause a poor score.

For WordPress sites, we keep a longer guide on Core Web Vitals for WordPress. Shopify stores have their own bottlenecks; see Shopify speed optimisation for the theme and app issues we see most often.

1. Stop the largest image being the slowest thing on the page

The largest image or banner is often the reason LCP is poor. Compress it, serve a modern format where you can, and do not lazy-load the hero image — the browser should fetch that first. Replace auto-playing background videos with a still image on mobile if the video is only decorative.

2. Cut what the browser has to download before it can paint

Every extra font, slider, chat widget and marketing pixel competes with the content. Load only the fonts you use, prefer system fonts where it will not hurt the design, and defer scripts that are not needed for the first view. If a plugin or app is not visibly doing something on the page, turn it off and measure again.

3. Reserve space so the layout does not jump

CLS usually comes from images, ads or embeds without width and height, or from banners that insert themselves above the content after load. Set dimensions on images, avoid inserting a bar at the top after the first paint, and be careful with web fonts that swap late and change the size of the text.

4. Measure a real page, not only the home page

A fast home page with a heavy product or blog template is a common pattern. Test the pages people actually land on. Use it alongside PageSpeed Insights or Search Console for the lab and field data.
